The myTUIN experience

This is a visual and interactive reference for the coding AI. It shows the intended feel, hierarchy, relationships and controlled vocabulary bindings of the app. It is not a technical specification and not a pixel-perfect design.

Build for the gardener

  • Calm, clear, earthy and practical.
  • Cards organise information; they do not bury it.
  • Show context and relationships, not isolated records.
  • Maps feel like a real garden, not a GIS application.
  • Recommendations explain themselves.
  • Recording something should be quick.
  • Never blur what you recorded, what you observed, what myTUIN inferred, what it recommends, and what actually happened.

How to read this reference

Every chip below a label shows the canonical vocabulary identifier the coding AI must store — never the display text. Display strings are localisation concerns. Rules, validation, import/export and database values all use the identifiers shown.

Semantic layersdata_origin evidence_type information_state confidence — a fact, an observation, an inference and a recommendation are never the same record.
Planning vs. realityplanning_status is intent. activity_type+status is what happened. A plan is never evidence that an activity occurred.
Recommendationrecommendation_status, confidence, suitability_dimension, recommendation_factor_result and recommendation_reason_type are separate fields. Suitability is not confidence.
Sourcessource_status, evidence_type and knowledge_maturity describe provenance. Verified does not mean guaranteed correct.
